# reqval — AI-агент проверки требований

BCC-HUB x MNU FinTech Hackathon. Агент проводит статическое ревью документа требований до начала разработки
по ISO/IEC/IEEE 29148:2018 (п. 5.2.5, 5.2.6, 5.2.7) и IEEE Std 830-1998 (п. 4.3) и пишет отчёт на русском.

**Модель:** `anthropic/claude-sonnet-5.5` через [OpenRouter](https://openrouter.ai), ответы строго по JSON-схеме.
Прогон ≈ 2 минуты и ≈ $0.7. Агент проверяли и на бесплатном Google Gemini — работает, но результат заметно хуже
(см. [«Выбор модели»](#выбор-модели-замеры)).

## Быстрый старт

```bash
# 1. Python 3.10+
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. Ключ LLM
cp .env.example .env               # Windows: copy .env.example .env
# Откройте .env и впишите OPENROUTER_API_KEY (как получить — ниже)

# 3. Прогон (одна команда: путь к требованиям, путь к отчёту)
python -m reqval docs/requirements.md out/report.md
```

Отчёт ляжет по указанному пути (`out/report.md`), рядом — машиночитаемая копия `out/report.json`
и журнал всех обращений к модели `out/report.llm.jsonl`.
Если указать `out/report.html`, отчёт будет в HTML.

**Код выхода.** `0` — отчёт записан, проверка выполнена полностью; `2` — ошибка запуска (нет файла, ключа,
неверный формат), отчёт не записан; `3` — отчёт записан, но часть шагов не выполнена (модель не ответила):
итог в отчёте — «ПРОВЕРКА НЕ ЗАВЕРШЕНА», перед сдачей прогон нужно повторить.

**Входной документ.** Документ организаторов лежит в `docs/requirements.md` без изменений
(источник: https://github.com/BCC-HUB/ai-requirements-validator-task). Другой файл или формат
передаётся тем же способом, например `python -m reqval docs/requirements.pdf out/report.md`.

**Версия агента в паспорте.** Агент берёт её из git (тег и коммит). Запускайте его из клона репозитория,
без незакоммиченных изменений: иначе в паспорте и в логе будет предупреждение, что отчёт нельзя
воспроизвести по коммиту. Без git версию можно задать вручную: `AGENT_VERSION=v1.0 python -m reqval …`.

**Пример результата** без запуска: [`examples/claude-sonnet-5.5/report.md`](examples/claude-sonnet-5.5/report.md)
(+ JSON и журнал обращений к модели).

### Как получить ключ OpenRouter (основная модель)

1. Зарегистрируйтесь на https://openrouter.ai и пополните баланс (прогон стоит ≈ $0.7).
2. Откройте https://openrouter.ai/settings/keys → **Create Key**; при создании задайте лимит расходов.
3. Вставьте в `.env`: `OPENROUTER_API_KEY=...`. Модель уже указана: `OPENROUTER_MODEL=anthropic/claude-sonnet-5.5`.

Файл `.env` в git не попадает (см. `.gitignore`).

### Бесплатная альтернатива: Google Gemini

1. Откройте https://aistudio.google.com/apikey, войдите в Google-аккаунт, нажмите **Create API key**.
2. Вставьте в `.env`: `GEMINI_API_KEY=...`.
3. Запуск: `python -m reqval docs/requirements.md out/report.md --provider gemini`
   (основная `gemini-3.8-flash`, при перегрузке — запасная `gemini-3.5-flash-lite`; обе есть на бесплатном тарифе).

Бесплатный тариф ограничен по числу запросов в день, а `gemini-3.8-flash` бывает перегружена (ошибка 503) —
тогда агент повторяет запрос, переходит на запасную модель, а если модель недоступна совсем, пишет отчёт
с итогом «ПРОВЕРКА НЕ ЗАВЕРШЕНА» и кодом выхода 3.

### Выбор модели: замеры

Один и тот же документ (`docs/requirements.md`), один агент, сравнение с эталонным списком из 26 дефектов
документа (противоречия, пропуски, ошибки API), составленным при ручном ревью:

| Модель | Найдено эталонных дефектов | Время | Стоимость | Замечания |
| :--- | :-: | :-: | :-: | :--- |
| **`anthropic/claude-sonnet-5.5`** (OpenRouter) | **25–26 из 26** (4 прогона; сдаваемый `v1.0` — 26) | ≈ 2 мин | ≈ $0.7 | Конкретные формулировки, точные цитаты, ни одной отброшенной (выдуманной) цитаты |
| `google/gemini-3.8-flash` (через OpenRouter) | 24 из 26 | ≈ 12 мин | ≈ $0.4 | Долго «рассуждает»; ответ нарезки обрезался по лимиту длины |
| `google/gemini-3.1-flash-lite` (через OpenRouter) | 21 из 26 (2 прогона) | ≈ 30 с | ≈ $0.04 | Пропускает разделы при нарезке, общие формулировки, завышает критичность |
| `gemini-3.8-flash` (бесплатный Gemini API) | — | — | бесплатно | Во время замеров отвечала 503 (перегрузка), прогон не завершился |

Все модели Gemini стабильно пропускали одно из главных противоречий документа: Ф-3 («не больше одного push
в месяц») против Ф-4 («push при следующем достижении порога независимо от истории»). Поэтому сдаваемый отчёт
сделан на Claude. Модель записана в паспорте отчёта; у Claude не задаётся `temperature` (постоянное мышление),
поэтому повторный прогон может немного отличаться формулировками и числом замечаний.

## Поддерживаемые форматы

PDF (с текстовым слоем), DOCX, Markdown, TXT.

В PDF таблицы читаются по ячейкам (строка таблицы → ячейки через « | », как в Markdown), перенесённые вёрсткой
строки абзаца склеиваются, страница указывается в ссылках на место. Таблицы без рамок разбиваются на колонки
по широким разрывам между словами; пустую строку такой таблицы в PDF не отличить от пустого места.
Сканы без текстового слоя не поддерживаются — агент сообщит об этом.

**Повреждённые и «не те» файлы.** Формат определяется по содержимому, а не только по расширению: DOCX,
сохранённый с расширением `.pdf` (и наоборот), читается как есть, с предупреждением в логе и в журнале отчёта.
Текст в Windows-1251 или UTF-16 перекодируется (тоже с пометкой), BOM убирается. Обрезанный или битый PDF/DOCX,
PDF с паролем, старый `.doc`, RTF, zip-архив, двоичные данные, пустой файл, папка вместо файла, нет прав на
запись отчёта — понятное сообщение и код выхода 2, без трассировки Python.

## Параметры

| Параметр | Назначение |
| :--- | :--- |
| `--model` | Другая модель провайдера, например `google/gemini-3.8-flash` для OpenRouter или `gemini-3.5-flash-lite` для Gemini |
| `--provider` | `openrouter` (по умолчанию, `anthropic/claude-sonnet-5.5`), `gemini` (бесплатный Google Gemini), `openai` (любой OpenAI-совместимый API, в т.ч. Ollama), `offline` — только формальные правила без LLM (итог «ТОЛЬКО ФОРМАЛЬНАЯ ПРОВЕРКА») |
| `--batch-size` | Сколько требований проверять за один запрос (по умолчанию 6) |
| `--no-json` | Не сохранять JSON |
| `--concurrency N` | Параллельных запросов к модели. По умолчанию: Gemini — 1 (лимит запросов в минуту на бесплатном тарифе), OpenRouter — 4. Отчёт от этого не меняется: результаты собираются в исходном порядке |
| `--cache [DIR]` | Брать повторяющиеся ответы модели из кэша (для отладки; по умолчанию выключено, в паспорте отмечается) |
| `-v` | Подробный лог |

## Как работает

1. **Чтение** документа с номерами строк и путём разделов (для PDF разделы определяются по шрифтам заголовков).
2. **Нарезка**: LLM выделяет требования с дословными цитатами; каждая цитата сверяется с текстом
   (точно, затем нечётко), иначе требование отбрасывается. Требованиям без номера присваивается свой ID (R-xx).
3. **Формальные правила** (без LLM): заглушки и TBD, пустые поля, незаполненный чек-лист и согласование,
   требования без идентификаторов, размытые термины, временные характеристики без условий измерения.
4. **Проверка каждого требования** по C1–C9: необходимость, уместность (без лишних проектных решений),
   однозначность, полнота, единичность, осуществимость, проверяемость, корректность, соответствие/прослеживаемость.
5. **Проверка набора** по S1–S8 в два прохода: согласованность (противоречия между требованиями, критериями
   приёмки, частями A и B) и полнота/управляемость.
6. **Верификация ссылок**: каждая цитата дефекта ищется в документе; дефекты без подтверждённой цитаты не попадают
   в отчёт и перечисляются в приложении «Отброшенные замечания модели». Если модель не ответила на нарезке, требования
   выделяются правилами; если не ответила на проверке — итог «ПРОВЕРКА НЕ ЗАВЕРШЕНА», а не «ГОТОВ».
7. **Итог**: правило «есть критичные → НЕ ГОТОВ, есть значительные → ГОТОВ С ОГОВОРКАМИ, иначе ГОТОВ»
   плюс приоритеты исправления от модели.

конкретного требования (C8), и то же противоречие на уровне набора (S2) в сводке считаются одним дефектом.

## Журнал обращений к модели

`out/report.llm.jsonl` — по строке на каждое обращение: время, шаг, модель, параметры, SHA-256 промпта,
токены, стоимость, `finish_reason`, исход (`ok`, `schema_error`, `error`, `fallback`, `skipped`, `cache`) и сырой
ответ модели. Ключ API в журнал не попадает. В паспорте отчёта указаны имя журнала, число записей и его SHA-256 —
так отчёт однозначно связан с прогоном, который его сформировал. Неудачные ответы дополнительно сохраняются в
`out/llm_debug/`.

## Устойчивость к сбоям модели

- Временные ошибки (429, 5xx, таймаут) повторяются с паузой; ответ не по схеме — переспрашивается с указанием ошибки.
- Запасная модель: `GEMINI_FALLBACK_MODEL` / `OPENROUTER_FALLBACK_MODEL` в `.env`. Если основная модель недоступна
  после всех попыток, шаг повторяется на запасной; в паспорте видно, какая модель на каком шаге отвечала.
- Предохранитель: если модель недоступна `LLM_BREAKER_AFTER` шагов подряд (по умолчанию 2), остальные шаги
  пропускаются, отчёт пишется сразу с итогом «ПРОВЕРКА НЕ ЗАВЕРШЕНА» и кодом выхода 3.
- OpenRouter: агент сам подбирает формат структурированного ответа, который поддерживает модель
  (строгая JSON-схема; без `seed`; без `temperature` для моделей с постоянным мышлением; вызов инструмента;
  схема в промпте). Выбранный режим указан в паспорте.

## Состав отчёта

Паспорт прогона (документ, SHA-256, дата, модель, версия агента — git-коммит), методика, таблица нарезки,
матрица критериев и замечания по каждому требованию, проверка набора, сводка (число требований и дефектов,
критичные дефекты, группы ТЗ: непроверяемые / противоречивые / неполные формулировки), итог с приоритетами
исправлений, приложение с журналом прогона и отброшенными замечаниями модели.

## Структура

```
reqval/
  cli.py        точка входа
  loader.py     чтение PDF/DOCX/MD/TXT
  anchor.py     привязка цитат к тексту
  criteria.py   критерии 29148/830
  rules.py      формальные проверки
  prompts.py    промпты
  llm.py        Gemini / OpenAI-совместимые провайдеры, ретраи
  pipeline.py   конвейер
  report.py     отчёт Markdown/HTML/JSON
tests/          офлайн-тесты с фиктивной моделью: python -m pytest -q
```

## Скорость

Пакеты требований и проверка набора не зависят друг от друга и при `--concurrency` > 1 идут параллельно
(проверка набора — самый долгий запрос — отправляется первой). Пауза `LLM_MIN_INTERVAL` между запросами
общая для всех потоков, поэтому лимит запросов в минуту соблюдается и в параллельном режиме.

## Лимиты бесплатного тарифа Gemini

Прогон занимает около 10–15 запросов. На бесплатном Gemini запросы идут по одному с паузой 4 с
(`LLM_MIN_INTERVAL`, `LLM_CONCURRENCY`), при ошибке 429/503 агент ждёт и повторяет запрос, затем переходит
на запасную модель `GEMINI_FALLBACK_MODEL`.
